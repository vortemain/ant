# Agent handoff guide

## Goal
**Read `docs/vision.md` first.** Ant is a Bun/Expo-class, **local-first** build tool that covers everything — every platform (Android, iOS, web, desktop, backend) and language — with very few commands (`ant init`, `ant build`), very fast builds on the developer's own machine, and a polished dashboard. Offloading to the owner's own servers (`ant server deploy`) is an optional extension, never a requirement (D-026). Underneath it is a trustworthy local-first build engine that grows into self-hosted remote, hybrid, distributed, managed, and enterprise execution. Work follows the product roadmap (phases P1–P9) at the top of `docs/plan.md` (decision D-016): user-facing simplicity first; plumbing commands are internals, not the product's front door. The attached master specification is a user-provided requirements source; it is not evidence that any capability has already been implemented.

## Before taking ownership
1. Read `README.md`, `docs/architecture.md`, `docs/plan.md`, and `docs/requirements-traceability.md`.
2. Inspect repository state and preserve existing edits. Do not assume the repo is clean.
3. Find the active milestone and its acceptance criteria in `docs/plan.md`.
4. Confirm relevant toolchain versions and current tests/build state before changing code.
5. Update the decision log and traceability entries when changing a contract or scope.

## Working agreements
- Keep one canonical contract per concept. Coordinate changes across dependents and document migration implications.
- Prefer a complete, reviewable vertical slice over disconnected crates or UI mockups.
- Do not mark capabilities supported until end-to-end behavior, failure handling, security, observability, docs, and applicable validation exist.
- Treat project build code and plugins as untrusted. Default to least privilege; do not make cacheability or hermeticity assumptions.
- Never put credentials in ordinary action metadata, logs, fixtures, or cache keys. Secret values must not cross trust boundaries as plain environment metadata.
- Use stable Rust by default. Keep dependencies justified and centralized. Avoid premature crate splitting.
- Update this handoff guide when repository workflow or ownership conventions change.
- Do not claim tests, benchmarks, compatibility, security, or deployment succeeded unless actually verified.

## Ownership handoff template
For each work item, record: owner; files/contracts owned; dependencies; acceptance criteria; validation performed and result; known risks; next action. Avoid parallel edits to the same contract files unless explicitly coordinated.

### Direction (owner's decisions, in force)
- **Ant is local-first (D-026).** Most developers have no VPS and build on their own, often old, laptop. Lead every feature, doc, and pitch with fast local builds; remote/VPS execution (coordinator, workers, shared remote cache, `ant server deploy`) is a later, optional extension (roadmap P8). Do not describe servers apologetically ("optional") in marketing copy either: the owner wants a confident, benefit-first pitch (see README).
- **Owner's speed goal:** developers on an ordinary or old laptop should get builds ~10× faster than what they are used to. Get there by not repeating work (reuse), by keeping laptop work proportional to what changed, and only later by offloading.
- **Local reuse is trusted like Turborepo (D-028, owner's choice).** Proof-based reuse (sandbox + network isolation) stays the only way results are *shared*; plain `ant build` additionally reuses results built on the same machine. Never let local-only results reach a shared store.
- **No `Co-Authored-By` trailers** in commit messages and no generated-by footers in PR bodies (owner's request; history was rewritten to remove them). The owner's Claude Code settings already set `attribution` to empty.
- Work on a branch, keep CI green on both OSes, and merge to `main` only when the owner says so (they usually answer "Yes, merge to main"). Fast-forward merges keep history linear; rebase first if `main` moved.

### Gotchas learned the hard way
- **Editing files with Python heredocs mangles escapes**: `\t`, `\0`, `\A` inside `'''...'''` become real tabs/NUL bytes. One real NUL byte landed in a Rust string literal this session. Prefer the Edit tool, or write the patch script to a file and check `git diff`. Scan for NUL bytes before committing (`git ls-files` + a byte check).
- Tests that run `ant build`/`ant run` must set `ANT_CACHE_HOME` (see `crates/ant-cli/tests/front_door.rs`) so they do not share the user's change-detection cache or local results store.
- Gradle: never pass `--offline` together with the remote task cache (Gradle silently disables the remote cache offline; D-025). The local Windows machine has Java 17 but no Android SDK; the Windows `ant build` path is proven without one by the stub-wrapper e2e (`crates/ant-cli/tests/gradle_build.rs`), and real-Android work is verified in the `bench-android` workflow on GitHub runners.
- The auto-mode permission checker may block deleting remote branches and other destructive git operations; ask the owner, do not work around it.
- Benchmarks run in CI (`bench.yml`, `bench-android.yml`); each run may land on a different CPU model, so compare Ant with the native tool *within* one run.
