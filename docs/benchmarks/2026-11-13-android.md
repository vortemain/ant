# Android: Gradle vs. Ant's shared remote cache (2026-11-13)

**Scope:** the first Android build through Ant. One real app, one GitHub-hosted Linux runner, a loopback coordinator and one sandboxed worker on the same machine (no real network). Characterizes where time goes; not a general performance claim.

## Method

- Workflow: [`.github/workflows/bench-android.yml`](../../.github/workflows/bench-android.yml); script: [`benchmarks/android/run.sh`](../../benchmarks/android/run.sh). Run 43465528849, Ant commit 6e29312.
- Subject: **JetNews** from `android/compose-samples` at `25631e8f` (Jetpack Compose, Kotlin, Gradle 9.5.0 wrapper, one application module), task `assembleDebug`.
- Preparation (not measured as a comparison): one online Gradle build fills a dependency cache; its `caches/modules-2` is copied into the project as `.gradle-deps/` (read-only dependency cache, lock files removed) and the Gradle distribution zip is placed next to `gradle-wrapper.properties` with a relative `distributionUrl`. Result: 415 MB, 1,417 files (271 MB of dependencies). This is what lets a worker with no network build it (D-024).
- Gradle baseline, at its best: `./gradlew --offline assembleDebug` with the same dependency cache, **daemon on, build cache on** (the project sets `org.gradle.caching=true`). Cold (fresh Gradle home), no change ×3 (warm daemon), fresh checkouts ×3 at other paths (warm daemon + warm local build cache).
- Ant: `ant adapt --adapter gradle`, then `ant remote run` against one `ant worker --sandbox` (bubblewrap, no network, `--offline`, Kotlin in-process): cold (empty shared cache), no change ×3, fresh checkouts ×3 at other paths with new timestamps.
- Runner: AMD EPYC 7763, 4 cores, 15.6 GiB, Ubuntu 26.04, Temurin 17.0.21, Android SDK from the runner image, bubblewrap 0.11.1. Raw data: [`results.csv`](../../benchmarks/android/results/2026-11-13/results.csv), [`environment.txt`](../../benchmarks/android/results/2026-11-13/environment.txt), the generated [`plan.json`](../../benchmarks/android/results/2026-11-13/plan.json). (The raw CSV's notes column contains commas in some rows; the script now uses semicolons.)

## Results (seconds, same run)

| Scenario | Gradle (daemon + build cache) | Ant (shared remote cache) |
|---|---:|---:|
| Cold | 156.88 | 158.97 |
| No change, same checkout (×3) | 2.18 · 1.76 · 1.57 | **0.66 · 0.86 · 0.86** |
| Fresh checkout, other path (×3) | 4.58 · 4.41 · 4.00 | **0.65 · 0.85 · 0.65** |

Every Ant re-run executed nothing and was served from the shared cache (executed=0, reused=1). The APK installed from the cache into a fresh checkout is a valid Android package (the script checks for `AndroidManifest.xml` inside it).

## Reading

- **Ant builds a real Android app.** Adapt → sandboxed, offline remote build → debug APK, on the first CI run.
- **Cold: a tie (159 s vs 157 s).** Shipping 415 MB to the worker and back costs ~2 s against a 2.5-minute Gradle build.
- **Unchanged and fresh checkouts: ~2–6× faster than Gradle at its best** (≈0.7–0.9 s vs 1.6–4.6 s), and unlike Gradle's local build cache, Ant's cache is shared: a teammate's machine or a CI runner gets the same ~0.7 s, where Gradle without that machine's warm daemon and build cache would pay the cold ~157 s.
- **Gradle's fresh-checkout number assumes the same machine** (warm daemon, local build cache). That is Gradle's best case, not a typical CI runner.
- Single worker on the same machine; no real network. Numbers on a VPS will differ. The dependency/distribution vendoring step is manual in the script today; `ant build` should do it automatically (next step).

## Run 2: shared Gradle task cache (D-025)

Run 43474904549, Ant commit 41ccd08, AMD EPYC 9V74 (a faster runner than run 1, so compare within the run). The worker now serves Gradle's remote build cache from the coordinator (`ant worker --sandbox --task-cache`). New scenario: append one private value to `JetnewsApplication.kt`, then rebuild. Raw data: [`2026-11-13-task-cache`](../../benchmarks/android/results/2026-11-13-task-cache/results.csv).

| Scenario (seconds) | Gradle (warm daemon + build cache) | Ant |
|---|---:|---:|
| Cold | 114.56 | 122.53 |
| No change (×3) | 1.37 – 1.40 | **0.59 – 0.79** |
| Fresh checkout (×3) | 3.48 – 4.90 | **0.58 – 0.78** |
| One file edited (×3) | **2.00 – 3.30** (incremental, same checkout) | 72.55 – 74.15 (fresh worker; 18 of 36 tasks from the task cache) |
| Teammate pulls the same edit | rebuild on their machine | **0.79** |

- The task cache works: the cold build stored 463 entries; every edit run took 18 of 36 Gradle tasks from it, which halved the cost of an edit (≈150 s → ≈73 s; run 1 had no task cache because `--offline` disables Gradle's remote cache).
- **Gradle still wins the single-developer edit loop by ~25×.** A warm daemon recompiles one Kotlin file incrementally using state left in `build/`; Ant's worker starts from an empty workspace, a cold JVM, and an unpacked distribution, and JetNews is one module, so the whole `:app` Kotlin compile and everything after it re-run.
- Where Ant wins is everything shared: unchanged and fresh checkouts and a teammate (or CI) picking up an edit someone already built, all under a second.
- Next steps to close the edit gap: keep warm per-project worker state (Gradle daemon and incremental `build/` state on a worker, trading strict freshness for speed, needing its own trust decision), and multi-module projects, where the task cache reuses whole unchanged modules.
